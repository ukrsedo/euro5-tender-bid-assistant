# Пам’ять ЄВРО5: перший етап

## Що реалізовано

Серверна пам’ять для тендерного помічника: версії профілю компанії, нотатки про замовника, журнал рішень щодо тендера, особисті налаштування співробітника. Дані не публікуються у GitHub. Одна база може обслуговувати інші інструменти ЄВРО5 після додавання аналогічного клієнта.

Це структурована основа пам’яті, не встановлений Mem0. Автоматичного вилучення фактів з розмов, семантичного пошуку, передачі даних у Mem0 або підмішування нотаток у AI-запит немає. Записи показуються поруч з результатами; бали, калькулятор і фінансові пороги не змінюються автоматично. Для застосування числових обов’язкових правил потрібна окрема структурована схема правил; вільний текст таким правилом не вважається.

## Підключення до наявного Worker

1. Створити окрему D1 базу `euro5-project-memory`. У її SQL console виконати `migrations/0001_project_memory.sql`. Спочатку перевірити на тестовій базі.
2. У наявного паливного Worker: Bindings → Add binding → D1 database. Variable name: `EURO5_MEMORY_DB`, database: створена база.
3. Додати текстову змінну `MEMORY_ENABLED` зі значенням `1` тільки після налаштування решти параметрів.
4. Додати secret `MEMORY_USERS` — JSON-масив облікових записів:

```json
[{"id":"operator-1","company":"euro5","role":"admin","token_sha256":"REPLACE_WITH_SHA256_HEX"}]
```

Для кожної людини створити окремий випадковий секретний ключ (наприклад 32 випадкові байти у hex — 64 символи), обчислити SHA-256 від тексту ключа. Записати лише hash у `MEMORY_USERS`, передати сам ключ відповідному користувачу захищеним способом. Не зберігати ключі/профіль/комерційні умови в репозиторії, HTML або config.js. Інші ролі: `editor`, `reader`. Редактор записує рішення і нотатки; адміністратор додатково змінює профіль компанії. Читач нічого не записує. Особисті налаштування ізольовані за серверним id; company визначається на сервері з ключа, не з запиту.
5. Опублікувати оновлений `worker.js`, зберігши всі наявні bindings і secrets. Це як і раніше один файл із наявним `Euro5CategoryAI` entrypoint.
6. Опублікувати `memory.js`, оновлені `app.js` та `index.html` разом. Завантажити тендер, ввести ключ у секції «Пам’ять ЄВРО5» і завантажити контекст.

Без MEMORY_ENABLED/бази/ключів пам’ять повертає 503; аналіз тендера продовжує працювати. Щоб вимкнути функцію, змінити MEMORY_ENABLED на 0. Заміна/видалення hash у secret відкликає ключ. Ключ не зберігається у localStorage/sessionStorage; лишається у полі пароля поточної сторінки до закриття доступу або виходу зі сторінки.

## Дата аналізу і версії

`available_at` — заявлений користувачем момент доступності інформації; `effective_at` — момент початку дії; `recorded_at` — реальний серверний момент запису. Час зберігається у UTC. API приймає точний ISO 8601 із часовим поясом, не лише день. Інтерфейс для дати оголошення без часу обирає 00:00 UTC, консервативно виключаючи подальші записи цього дня. За наявності точного часу оголошення/аналізу його треба вказати у полі моменту аналізу.

До контексту потрапляють лише записи з available_at і effective_at не пізніше моменту аналізу. У кожній групі виду/ключа береться остання внесена видима версія. Версія від 23 жовтня не замінює версію від 12 жовтня у зрізі на 13 жовтня. Введена сьогодні історична інформація допускається за наявності HTTPS-джерела і заявленої дати; сервер НЕ перевіряє, що в джерелі саме тоді було це твердження. Для строго відтворюваного прогнозу потрібен незалежний архів джерела. Текст пам’яті не є перевіреним фактом Prozorro.

Щоб додати нову версію, використати той самий ключ запису і вид. Різні факти/рішення повинні мати різні ключі. Профілі компанії та особисті налаштування доступні у всіх тендерах відповідної компанії; нотатки вибираються за кодом замовника, рішення — за поточним ID тендера. Максимум 100 актуальних записів у відповіді з явним прапорцем обрізання.

## Перевірки перед включенням

- Два користувачі ЄВРО5 бачать спільну нотатку, але не особисті налаштування один одного.
- Ключ іншої company не бачить жодного запису ЄВРО5.
- Читач не записує; editor не змінює профіль компанії.
- Новіший результат поточного тендера не з’являється у ранішому зрізі.
- Запис не змінює бал рейтингу й не підміняє поточні ціни.
- Історичне джерело перевіряється людиною до використання у рішенні.

Локальні тести: `node scripts/test-project-memory.mjs` (Node 22+ із node:sqlite). Тести використовують справжній SQLite із адаптером D1; розгортання на Cloudflare та повний E2E із реальною базою перевіряються окремо.
