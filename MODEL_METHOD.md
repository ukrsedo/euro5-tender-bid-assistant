## Как работает фильтр

1. Проверяются CPV лота, моделируемая конкурентная процедура, бюджет от 1 млн грн без НДС и наличие успешного результата с допустимой ценой/числом участников. Наблюдения, не отвечающие этим ограничениям, в модель не входят.
2. Для спорных названий используются сохранённые позиции API. Проверяются идентификатор тендера, заказчик и дата изменения снимка не позднее 22.10.2026. Лот сопоставляется по названию и бюджету; единственный лот — по бюджету и номеру L1. При неоднозначности сопоставление не производится.
3. В многолотовой закупке используются только позиции нужного relatedLot. Проверяется каждый товар: описание, CPV, единица объёма/массы и положительное количество. Массу в литры автоматически не переводим. Смеси бензина и дизеля допустимы; наличие газа, масел, керосина или оборудования не позволяет считать весь бюджет чистой закупкой бензина/дизеля.
4. Если подробного API-снимка нет, используются явно определённые название и CPV. Общие названия «Нафта і дистиляти», «Паливо», «Лот 1» больше не являются окончательным основанием для исключения. Если BI подтверждает ровно один товар, допустимо уточнение по явному описанию, физической единице и количеству. Для нескольких товаров одного описания недостаточно.
5. Неразрешённые случаи сохраняют отдельную причину исключения, а не ошибочную метку другого товара. «Для генераторов», «для ремонта» и «для полива» не означают закупку оборудования, работ или масел.

Сохранённый состав API не переносит в базу новые результаты, предложения или победителей. Исходные статусы, суммы и участники берутся из сохранённого среза BI. Проверка всей исходной базы через API не выполнена; для явно определённых старых названий действует описанный резервный способ классификации.

## Обучение и проверка

Сохранены архитектура StandardScaler + LogisticRegression(C=1), отдельная логистическая калибровка и 13 признаков: бюджет; число предыдущих лотов заказчика, среднее число участников, доля одного участника, последний результат; вид топлива; тип процедуры; талон/налив. История заказчика доступна только после даты завершения соответствующего лота; собственный результат, будущие и результаты того же дня не используются.

Обучение контрольной версии: объявления с 2025 года с результатами до 01.07.2026. Калибровка — июль–август с результатами до 01.09. Независимая проверка — 468 завершённых лотов, объявленных в сентябре–октябре: accuracy 73,29%, AUC 0,7122, Brier 0,1861. Это не вероятность победы и не доказательство улучшения против предыдущей версии: состав контрольной выборки изменился.

Рабочие коэффициенты обучены заново на результатах до 01.09; финальная калибровка — сентябрь–октябрь до среза. Последняя уже использует контрольные наблюдения, поэтому приведённая независимая оценка относится к более ранней контрольной версии, а не к финальным коэффициентам.

Ценовые позиции пересчитаны по квартилям 25/50/75/90% с округлением скидки вверх до 0,25 п.п. Рынок — 90 дней, один участник — 730 дней; отдельно по бензину/дизелю/смешанному топливу. Историческая конкурентность проверяется последовательно: для каждого контрольного объявления доступна только более ранняя история. Это контрольная частота, не вероятность победы.

## Даты и совместимость

Версия `2026-10-22-items-v2` применяется к объявлениям от 23.10.2026. Для 06–22.10 сохранены коэффициенты и ценовые таблицы версии 05.10; тестовый тендер от 13.10 не пересчитывается с будущими данными. Frontend различает обновлённый Worker и старую версию 22.10: до Deploy сохраняет соответствующие старые ценовые таблицы.

Сохранены исправление истории заказчика, концентрация побед, пятидневный риск от даты подачи, проектная память и прочие актуальные функции Worker. Новые переменные, секреты и привязки не требуются. `/health` после Deploy: `2026.10.23-fuel-filter-v2`.

Ограничения: предыдущий исходный код обучения отсутствовал, расчёт восстановлен; порог без НДС использует конвенцию приложения деления на 1,2, без восстановления исторических ставок; индивидуальный НДС победителя независимо не восстанавливается. Дата последнего изменения статуса консервативно определяет доступность результата.

## Воспроизведение

Архив содержит исходный срез, состав BI, сохранённые ответы API, обогащённую выборку и модели. Все связи проверяются по ID и датам. Зависимости обучения зафиксированы в `scripts/requirements-model.txt`.

```sh
python3 scripts/enrich-fuel-training.py bi-fuel-all-2026-10-22.jsonl.gz bi-lot-composition.jsonl.gz tender-items.jsonl training-enriched.jsonl.gz
python3 scripts/retrain-model.py training-enriched.jsonl.gz models
python3 scripts/build-model-assets.py
python3 scripts/test-fuel-filter.py
python3 scripts/test-model-temporal.py
node scripts/test-model-version.mjs
node scripts/test-buyer-recovery.mjs
```

Продолжение получения позиций, с сохранением контрольных точек:

```sh
python3 scripts/fetch-fuel-items.py data/fuel-item-check-targets.json tender-items.jsonl
```

Этот скрипт делает запросы последовательно с интервалом минимум 2 секунды и прекращает работу при 429, сохраняя Retry-After и оставшийся объём в сообщении. Он не повторяет успешно сохранённые тендеры. Последующий запуск проверяет дату снимка; обновлённые после среза снимки не подходят для исторического анализа на 22.10.
