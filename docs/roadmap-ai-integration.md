# Підключення ШІ Євро 5 без нового ключа

Ключ OpenAI залишається в наявному Worker `euro5-tender-bid-assistant`. Новий ключ не створюється й не копіюється. `AI_API_KEY`, `AI_API_URL` та `AI_MODEL` використовуються з цього Worker. Модель залишається тією, яку там налаштовано.

## Оновлення в Cloudflare

1. Відкрийте **euro5-tender-bid-assistant → Edit code**. Замініть код файлом **01_AI_Backend/worker.js** з архіву та натисніть **Deploy**. Файл зберігає наявний код тендерного помічника й додає окрему внутрішню точку входу `Euro5RoadmapAI`. Наявні секрети й прив’язки залиште.
2. Відкрийте **euro5-change-roadmap → Edit code**. Замініть код файлом **worker.js** з кореня архіву та натисніть **Deploy**. Наявні `DB`, `ACCESS_PASSWORD`, `SESSION_SECRET` та `LOGIN_LIMITER` залиште.
3. У **euro5-change-roadmap → Bindings → Add → Service binding** додайте зв’язок:

| Поле | Значення |
|---|---|
| Назва прив’язки / Variable name | `EURO5_REPORT_AI` |
| Worker / Service | `euro5-tender-bid-assistant` |
| Entry point | `Euro5RoadmapAI` |

Збережіть і застосуйте зміни. Якщо використовується конфігурація Wrangler, додайте до **наявної** конфігурації цей фрагмент `services`; не замінюйте ним конфігурацію бази чи секретів:

```json
"services": [
  {"binding":"EURO5_REPORT_AI","service":"euro5-tender-bid-assistant","entrypoint":"Euro5RoadmapAI"}
]
```

## Перевірка після публікації

- Перезавантажте сторінку. Розділ 03 називається **«Ресурси та строки»**, дорожньої карти в ньому немає.
- Оберіть **«Тестове введення даних»**. У розділі 03 або 04 натисніть **«Сформувати звіт ШІ та дорожню карту»**.
- Успішний результат має керівне резюме, чотири аналітичні розділи, назву моделі й одну дорожню карту з усіма діями. Тестовий звіт не записується до бази.
- Для фінального режиму спочатку дочекайтеся **«Збережено на сервері»**. Після генерації має з’явитися **«Фінальний звіт збережено у спільній базі Євро 5»**.
- Перезавантажте сторінку, оберіть фінальний режим і відкрийте звіт: він відновлюється без нового виклику моделі, якщо оцінки й параметри не змінилися.

## Як формується результат

Сервер перевіряє введені дані й сам обчислює рейтинг, ресурси, залежності та графік. ШІ отримує ці результати, стратегічні вводні та коментарі клієнта. Він пояснює пріоритети, розбіжності, припущення та рішення для обговорення. ШІ не змінює бали, ресурси чи строки і не створює власної другої дорожньої карти.

Фінальні звіти зберігаються в новій таблиці `roadmap_reports` у тій самій D1-базі. Таблиця створюється автоматично. Звіт пов’язаний зі станом відповідей і версією методики; зміна відповідей потребує нового звіту. Повторний запит за незмінними даними повертає вже збережений результат. Якщо інший учасник змінить оцінки під час генерації, застарілий звіт не записується.

Тестові оцінки й звіт не записуються у пам’ять рішення, але передаються OpenAI для виконання запиту. Для OpenAI використано `store:false`; це налаштування не є гарантією відсутності службового зберігання у провайдера. Автоматичних запитів до моделі під час редагування немає. Виклики оплачуються в наявному API-проєкті Євро 5.

## Межі перевірки

Локальні перевірки виконані з реальною SQLite та імітацією зовнішньої моделі. Перевірено авторизацію, ізоляцію тестових даних, збереження/відновлення, кешування, зміну оцінок під час генерації, обидва формати API та безпечне відображення тексту. Реальний виклик OpenAI через Cloudflare і браузерний сценарій після публікації ще потребують перевірки: доступу до Cloudflare та значення наявного секрету в цьому середовищі немає.

Джерела технічної інтеграції: https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/rpc/ та https://developers.openai.com/api/reference/python/resources/responses/methods/create.
